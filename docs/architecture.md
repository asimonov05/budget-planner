# Архитектура

## Контур развертывания

В production работает один контейнер и один процесс Uvicorn. FastAPI обслуживает `/api/v1`, OpenAPI и собранную React SPA. Неизвестный API-маршрут возвращает JSON 404 и не перенаправляется на `index.html`; SPA fallback применяется только вне API.

SQLite находится в `/data/budget.sqlite3`. В volume монтируется каталог целиком, чтобы WAL и SHM всегда находились на той же локальной файловой системе. NFS/SMB и синхронизируемые облачные каталоги не поддерживаются. Бэкапы находятся в отдельном `/backups` и не раздаются как static.

```text
browser -> :8000 FastAPI/Uvicorn -> services -> calculation core
                    |                 |
                    |                 -> repositories -> SQLite /data
                    -> /app/static

CLI -> migrations / Online Backup API -> /backups
```

## Слои backend

Маршруты отвечают за HTTP-контракт и аутентификацию; схемы — за валидацию; application services — за транзакционные сценарии; расчетное ядро — за чистые детерминированные формулы; repositories — за SQLAlchemy. GET-запросы не создают факты и не меняют финансовое состояние.

Финансовые операции, перевод, проведение плана, движения резерва, batch-редактирование и подтверждение импорта атомарны. Редактируемые сущности имеют версию; устаревшая запись получает HTTP 409. API поддерживает idempotency key для повторяемых команд; UI передаёт его для операций, переводов, сверки плана, целей и оплат кредита.

## SQLite

Каждое соединение включает `foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout=5000` и `synchronous=FULL`; приложение проверяет фактически примененные значения. Миграции Alembic запускаются до HTTP-сервера. Если текущая Alembic revision отстает от head, перед upgrade создается консистентный Online Backup; обычный restart лишних копий не создает.

Образ использует системную SQLite Alpine 3.24 и дважды проверяет `sqlite3.sqlite_version_info >= (3, 51, 3)`: при сборке и каждом старте. Проверяется именно библиотека Python-драйвера, не вывод отдельной CLI-утилиты.

## Frontend и темы

React SPA хранит только локальные предпочтения интерфейса; финансовое состояние всегда приходит из API. Выбор темы имеет три значения: `light`, `dark`, `system`, а независимая цветовая схема — `forest`, `ocean`, `plum`, `amber`. Предпочтения сохраняются в `localStorage`; вычисленная яркость устанавливается атрибутом `data-theme`, а схема — `data-color-scheme` на корневом HTML-элементе.

Небольшой синхронный bootstrap в `index.html` применяет сохранённые значения до загрузки React и CSS-отрисовки. React-провайдер затем поддерживает `color-scheme`, `theme-color` и подписку на `prefers-color-scheme` для системного режима. Настройки не синхронизируются с сервером и не входят в бэкап или экспорт проекта.

## Offline и границы

После сборки нет CDN, удаленных шрифтов, телеметрии или внешней авторизации. P0 не требует Redis, очередей, отдельной СУБД, банковской синхронизации, мультивалютности или нескольких пользователей. Вертикальное масштабирование допускается, несколько реплик приложения — нет.

## Безопасность контейнера

Runtime-пользователь `budget` имеет UID/GID 10001. Root filesystem read-only, временный каталог — ограниченный `tmpfs`, capabilities удалены, `no-new-privileges` включен. Первый named volume наследует владельца каталога из образа, поэтому `chmod 777` не нужен. Docker socket не подключается.
