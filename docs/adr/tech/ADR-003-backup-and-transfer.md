# ADR-003: ZIP — перенос данных; backup PostgreSQL — внешняя ответственность

**Статус:** принято.

Приложению нужен перенос финансовых данных между установками, но оно не должно
брать на себя управление физическими резервными копиями PostgreSQL. За
аварийное восстановление БД, расписание копий, их хранение, шифрование и
проверку отвечают внешние механизмы инфраструктуры.

Канонический ZIP — единственный поддерживаемый приложением механизм полного
экспорта и импорта финансовой модели. Он переносится в пустую установку и не
содержит пароль, сессии и локальные пути.

Таким образом, приложение отвечает на вопрос «как экспортировать или
импортировать финансовые данные», а вопрос «как восстановить этот сервер»
остаётся за внешним backup PostgreSQL.

## Последствия

- API, UI и CLI приложения не должны создавать, хранить, скачивать или
  восстанавливать `.dump`/физические копии БД.
- Канонический ZIP должен поддерживать экспорт и импорт с проверкой формата,
  версий и связей данных.
- Существующая поддержка `.dump` считается legacy и должна быть удалена из
  приложения, документации и проверок отдельной задачей миграции.
