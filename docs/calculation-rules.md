# Правила расчетов

## Деньги, резервы и свободный остаток

Все суммы — целые минимальные единицы валюты. Для каждого момента:

```text
C = сумма остатков денежных счетов
R = сумма резервов целей
F = C - R
```

Резерв — часть существующих денег, не отдельный актив. Движения:

| Событие | ΔC | ΔR | ΔF |
|---|---:|---:|---:|
| Внешний доход X | +X | 0 | +X |
| Расход свободных денег X | −X | 0 | −X |
| Выделение в цель X | 0 | +X | −X |
| Освобождение резерва X | 0 | −X | +X |
| Расход из резерва X | −X | −X | 0 |
| Возврат в резерв X | +X | +X | 0 |
| Перевод между счетами X | 0 | 0 | 0 |

Переход месяца:

```text
C_end = C_start + external_income - external_expense + adjustments
R_end = R_start + allocations - releases - goal_expenses + goal_refunds
F_end = C_end - R_end
```

Возврат уменьшает расход, а не создает доход. `goal_expenses` уже входит в `external_expense`. Отрицательный денежный баланс и прогноз сохраняются с предупреждением; резерв не уходит в минус неявно.

## Примерные ежемесячные расходы

У расходной категории можно включить ежемесячную оценку. Для каждого открытого месяца берутся до трёх предыдущих завершённых календарных месяцев, начиная не раньше даты начала учёта и появления первого счёта. Для будущих месяцев окно заканчивается перед текущим месяцем: прогнозы не учатся на собственных оценках. Месяц без трат входит в среднее как ноль. В истории учитываются расходы за вычетом возвратов, но не расходы целей и платежи, связанные с кредитами. Отрицательный итог отдельного месяца принимается за ноль. Если завершённых месяцев пока нет, оценка не добавляется.

Пусть `A` — среднее по истории, `F` — обычный факт категории в прогнозируемом месяце, `P` — ещё ожидаемые планы этой категории, `C` — весь факт категории, `L` — действующий лимит. Тогда `average_gap = max(0, A − F − P)`, `budget_gap = max(0, L − C − P)` при наличии лимита, а в расходный прогноз добавляется `max(average_gap, budget_gap)`. Поэтому факт, планы и лимит не прибавляются повторно. В строке «Примерные расходы» показывается только часть `max(0, average_gap − budget_gap)`, которая появилась именно из исторической оценки. Оценка не имеет точной даты и делает дневной прогноз неполным.

## Кредиты и досрочное погашение

Для расчётного аннуитетного графика задаются известный остаток основного долга на дату, годовая ставка, дата первого платежа и конечная дата. Даты платежей идут по месяцам; последний платёж корректируется до полного погашения. Одинаковый регулярный платёж подбирается в целых копейках так, чтобы погасить долг к конечной дате.

Проценты начисляются за фактическое число календарных дней между датами, отдельно для каждого года с делителем 365 или 366. При простом методе они считаются только на непогашенный основной долг. При сложном методе расчёт применяет ежедневную капитализацию. На каждом платеже сначала покрываются начисленные проценты, остаток уменьшает основной долг. Переплата в этом прогнозе — сумма будущих процентов; комиссии банка и страховка не включены.

Досрочное погашение в сценарии происходит после обычного платежа на выбранную дату графика. Дополнительная сумма уменьшает основной долг. Вариант «Сократить срок» сохраняет регулярный платёж и останавливает график после погашения; вариант «Уменьшить платёж» сохраняет конечную дату и пересчитывает оставшиеся аннуитетные платежи. Фактический досрочный платёж создаётся как расходная операция с выбранным кредитом и вариантом пересчёта.

Расчётный график является оценкой: кредитор может применять другую базу дней, дату списания, правила капитализации и округления. Для точного учёта договорного графика используйте ручные строки банка. Связанный с кредитом плановый платёж не дублирует его расчётный график в прогнозе; для ручного графика не дублируются месяцы с действующими строками.

## Зарплата до налога

Режим включается в настройках. Каждое правило относится к одному работодателю: месячная сумма до налога делится на аванс и окончательную выплату в заданных процентах. Аванс запланирован на 16–31-е число текущего месяца, остаток — на 1–15-е число следующего месяца. Число после конца короткого месяца заменяется последним днём. Если дата нерабочая, выплата переносится на предшествующий рабочий день по федеральному календарю пятидневки. Перенос может изменить месяц или налоговый год выплаты.

Для налогового резидента РФ применяется прогрессивная шкала НДФЛ 2025–2026 годов: 13% до 2,4 млн ₽ годовой базы, 15% от 2,4 до 5 млн ₽, 18% от 5 до 20 млн ₽, 20% от 20 до 50 млн ₽ и 22% сверх 50 млн ₽. Налог считается нарастающим итогом у **каждого работодателя отдельно** по году фактической выплаты и удерживается как при авансе, так и при окончательном расчёте. Налог нарастающим итогом округляется до целых рублей; удержание на конкретной выплате равно разности нового и предыдущего округлённого налога. Для запуска посреди года можно ввести уже начисленную у работодателя налоговую базу за текущий год **до месяца начала правила**. Выплаты месяца начала в эту базу не включают: правило рассчитывает их само. Доплаты, премии, отпускные, больничные, вычеты, региональные праздники и итоговый перерасчёт ФНС по доходам от нескольких работодателей пока не моделируются.

Федеральные переносы 2025–2027 годов внесены по утверждённым производственным календарям. Для более поздних лет используется календарь выходных и федеральных праздников без будущих переносов; такие даты и налоговый расчёт после 2026 года помечаются предварительными. В открытом месяце прогноз добавляет ожидаемую сумму **после налога**. Выплаты до даты начального остатка выбранного счёта не прибавляются к прогнозу, поскольку начальный остаток уже отражает деньги на эту дату; при этом их сумма участвует в годовой базе НДФЛ для последующих выплат. Связанный с выплатой фактический доход уменьшает её ожидаемый остаток на сумму связи. Закрытый месяц показывает только факт.

Нормативные источники: [ФНС о шкале НДФЛ](https://www.nalog.gov.ru/rn64/news/activities_fts/16639359/), [ФНС об удержании с аванса](https://www.nalog.gov.ru/rn10/news/activities_fts/13296383/), [Минтруд о сроках и переносе выплаты](https://mintrud.gov.ru/ministry/programms/28), [Правительство РФ о переносах на 2026 год](https://government.ru/docs/all/161028/), [постановление о переносах на 2027 год](https://www.consultant.ru/document/cons_doc_LAW_544706/).

## Лимит категории без двойного учета

Для открытого месяца обычной категории:

```text
B = эффективный лимит
A = чистый факт обычных расходов
P = непогашенный остаток конкретных ожидаемых платежей
U = max(0, B - A - P), если лимит задан, иначе 0
forecast = A + P + U
```

Целевые расходы не поглощаются обычным лимитом. Для закрытого месяца используется только факт. Полностью исполненное ожидание имеет остаток 0 даже при отклонении суммы; частичное — `max(0, plan - matched_fact)`.

## Цели

До первых расходов потребность равна `target - reserve`. Для расходуемой цели:

```text
need = max(0, target - net_goal_expenses - current_reserve)
```

Функция `split_evenly` раскладывает потребность по заданному числу взносов в целых копейках; остаток распределяется явно, поэтому сумма точно равна `need`. Полноценный календарь взносов и проверка обеспеченности к каждой промежуточной оплате пока не реализованы.

## Повторения и даты

Экземпляр текущей модели идентифицируется парой `plan_item_id + occurrence_month`; перенос даты хранится в override и не меняет исходный месяц. Отдельный номер выплаты и версии правил пока не моделируются. Правило «31-е» использует последний день короткого месяца и возвращается к 31-му. `null` в override означает наследование, `0` — явный ноль, отмена — отдельное состояние.

Календарь меняет сумму и дату только выбранного повторения через override, даже если дата переносится в другой месяц. Сброс удаляет override и возвращает значения серии. Изменение отвергается для закрытого месяца, отсутствующего или уже сверенного повторения; версия плана защищает от перезаписи более свежего изменения.

## Окна и точность прогноза

Смена отображаемого окна не сдвигает данные. Входящий остаток вычисляется от даты начала учета. Недатированные планы входят только в месячный итог; план без счета не входит в посчетный прогноз. Источник итоговой суммы должен раскрываться детализацией API.
