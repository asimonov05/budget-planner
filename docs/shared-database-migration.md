# Переход с двух PostgreSQL баз на одну

Переход `0006 → 0007 → 0008` выполнен 30 сентября 2026 года. До перехода `budget` содержала финансы владельца, `budget_auth` — одного пользователя и его сессии. После перехода единственная рабочая база `budget` содержит и учётную запись, и финансы; `budget_auth` удалена после проверки. Предмиграционные дампы сохранены локально в `.secrets/` и исключены из Git.

## Порядок для аналогичной установки

1. Убедитесь, что в `budget_auth.users` ровно один owner с `budget_database='budget'`. Migration job прерывается при другом состоянии: автоматическое объединение нескольких private DB требует отдельного отображения ID и не должно терять данные.
2. Сделайте внешние `pg_dump -Fc --no-owner --no-acl` обеих баз и проверьте `pg_restore --list`. Сохраните старый образ приложения.
3. Остановите API. Запустите `docker compose up -d migrate`; job копирует owner и сессии в `budget`, применяет Alembic `0007` и `0008`, включает составные tenant FK и `FORCE RLS` для финансовых данных и сессий, создаёт и выдаёт минимальные права runtime/debug-ролям.
4. Убедитесь, что migration job завершился с кодом `0`, затем запустите `docker compose up -d app` и проверьте `health/ready`, вход, счета, прогноз и ZIP-экспорт.
5. Сверьте количество финансовых строк с предмиграционным замером. Под ограниченной runtime-ролью проверьте: без `app.current_user_id` финансовые таблицы пусты; с owner ID доступны его строки; rollback и повторное использование соединения сбрасывают scope.
6. Сделайте и восстановите в изолированную базу новый dump. Только после проверки отзовите старую роль `budget_app` и удалите `budget_auth` (её dump хранится отдельно для отката).

## Откат

Остановите новый API, восстановите **оба** предмиграционных dump в отдельные `budget` и `budget_auth`, верните старый образ и его Compose-конфигурацию. Не запускайте старый образ на схеме `0007` или `0008`: обратная Alembic-миграция намеренно запрещена, потому что снятие tenant-изоляции может смешать данные пользователей. Перед повторной попыткой миграции создайте новые копии и проверьте, что активная база соответствует ожидаемой ревизии.
