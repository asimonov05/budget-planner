# Банковский PDF → CSV для планировщика бюджета

Подготовь два независимых файла: `transactions.csv` для фактических операций и `transfers.csv` для переводов между собственными счетами. Для работы нужны PDF-выписка и `accounts-for-import.json`, который пользователь скачивает из приложения. Доступ к коду проекта не требуется. Не отправляй банковский PDF, список счетов, OCR-текст или готовый CSV другим сервисам без явного решения пользователя. Работай с локальной копией; не меняй исходный PDF.

## 0. Получить ID счетов из приложения

1. Пользователь открывает **«Импорт/экспорт» → «Импорт» → «Табличный CSV»** и нажимает **«Скачать счета для ИИ»**. Полученный `accounts-for-import.json` он прикрепляет к запросу вместе с PDF и этим скиллом. Если список пуст, сначала создаёт нужные счета через **«Настройки → Счета»**, затем скачивает JSON заново.
2. В JSON у каждого счёта есть `account_id`, точное `name`, `currency`, `type`, `archived` и `initial_balance_date`. Остатков, паролей и токенов в выгрузке нет. `account_id` — внутренний ID приложения, а не номер счёта или карты из PDF.
3. Составь таблицу соответствия: счёт или маска карты в PDF → `account_id`/`name`/`currency` из JSON. Для архивного счёта и неоднозначного совпадения запроси подтверждение пользователя. Если нужного счёта нет, не выдумывай ID: попроси создать счёт и выгрузить список повторно.

Файл выглядит так; `7` здесь только пример, используй значения из файла пользователя:

```json
{
  "format": "budget-planner-account-reference-v1",
  "exported_at": "2026-10-04T10:00:00.000Z",
  "accounts": [
    { "account_id": 7, "name": "Основная карта", "currency": "RUB", "type": "bank", "archived": false, "initial_balance_date": "2026-01-01" }
  ]
}
```

## 1. Разобрать выписку

1. Определи банк, период, валюту, номер или маску счёта и поля таблицы. Сопоставь каждый банковский счёт с `accounts-for-import.json`. Не используй порядковый номер строки PDF или номер карты вместо `account_id`.
2. Извлеки текст и таблицы локальным PDF-инструментом. Для скана применяй локальный OCR и отдельно отмечай строки, где неуверенно прочитаны дата, сумма, знак, валюта или получатель. Проверяй многострочные описания и продолжения таблицы на следующей странице.
3. Используй дату проведения по счёту, если PDF различает дату операции и дату проводки. Исключи заголовки, остатки, итоги разделов, неподтверждённые и отменённые операции. Сохрани связь каждой будущей CSV-строки со страницей и исходной строкой PDF для сверки.
4. Расходы и доходы внешних контрагентов записывай как операции. Возврат расхода — `refund` с положительной суммой. Перевод другому человеку не считается переводом между своими счетами. Пару списание/зачисление между двумя *собственными счетами, заведёнными в приложении* объедини в одну строку `transfers.csv`, чтобы не задвоить движение. Комиссию банка запиши отдельным расходом.

## 2. Сформировать `transactions.csv`

Используй UTF-8 с BOM и разделитель `;`; даты — `YYYY-MM-DD`. Обязательные колонки: `date`, `amount`, `type`, `account_id` (допустимо точное `account`, но ID из JSON надёжнее). Рекомендуемый полный заголовок:

```csv
date;amount;type;account_id;currency;category;tags;description;comment;external_id;merchant_currency;merchant_amount;exchange_rate
```

- `type`: `income`, `expense`, `refund` либо `adjustment`. У дохода, расхода и возврата `amount` положительный; для `adjustment` допускается знак, но обязателен `comment`.
- `amount` — фактически списанная или зачисленная сумма **в валюте счёта**. `currency`, если заполнена, должна совпадать с валютой этого счёта. Сумму не округляй молча: соблюдай число минимальных единиц валюты.
- Для покупки или возврата в другой валюте вместе укажи `merchant_currency`, `merchant_amount`, `exchange_rate`. Курс означает единицы валюты счёта за **1** единицу валюты покупки. Пересчёт должен совпасть с `amount` с точностью до одной минимальной единицы. Используй фактические суммы или курс из выписки; курс ЦБ не подменяет курс банка. Если курс приходится вычислять из двух фактических сумм, явно укажи это в отчёте и проверь результат.
- `external_id` заполняй только устойчивым ID банковской операции, если он есть в PDF. Он защищает от повторного создания при загрузке другого файла. Не придумывай его. `tags` разделяй знаком `|`; категорию и теги не выдумывай, если пользователь не дал правила разметки.

Пример валютной покупки:

```csv
date;amount;type;account_id;currency;category;tags;description;comment;external_id;merchant_currency;merchant_amount;exchange_rate
2026-10-08;950,00;expense;3;RUB;Путешествия;;Билет;;bank-123;EUR;10,00;95
```

## 3. Сформировать `transfers.csv`

В примере `3` — условный ID: подставь реальный `account_id` из выгруженного JSON. Обязательные колонки переводов: `date`, `amount`, `from_account_id` (или точное `from_account`), `to_account_id` (или точное `to_account`). Рекомендуемый заголовок:

```csv
date;from_account_id;to_account_id;amount;from_currency;to_currency;exchange_rate;to_amount;comment
```

- `amount` списывается со счёта отправителя, `to_amount` поступает на счёт получателя. Оба счёта должны существовать и различаться. Если имена счетов совпадают, используй числовые ID; не заполняй одновременно имя и ID одного счёта.
- При разных валютах `exchange_rate` обязателен и означает единицы валюты **получателя** за **1** единицу валюты **отправителя**. Укажи фактический курс или рассчитай его из фактических сумм обеих сторон, затем проверь, что `to_amount` точно совпадает с результатом пересчёта. Если не совпадает, оставь строку на ручную проверку. При одной валюте курс пустой или `1`, а `to_amount` можно опустить.
- У CSV-переводов пока нет поля `external_id`. Повтор того же подтверждённого файла безопасен; похожий перевод в другом файле будет лишь отмечен кандидатом в дубль.

Пример:

```csv
date;from_account_id;to_account_id;amount;from_currency;to_currency;exchange_rate;to_amount;comment
2026-10-09;3;5;8000,00;RUB;USD;0,0125;100,00;Конвертация
```

`3` и `5` здесь условные ID; замени их значениями из `accounts-for-import.json`.

## 4. Сверить и передать

- Для каждого PDF-счёта и валюты сравни число проведённых строк, чистые списания/зачисления и изменение остатка с исходной выпиской. Отдельно проверь парные переводы, возвраты, комиссии и валютные покупки. Не включай одну банковскую строку и в операцию, и в перевод. В отчёте покажи сопоставление PDF-счетов с ID приложения.
- Записывай CSV стандартным CSV writer: цитируй поля с `;`, кавычками или переводами строк. Не превращай дату в локализованную строку и не форматируй суммы через binary float.
- На странице **«Импорт/экспорт»** выбери нужный тип CSV, кодировку, разделитель и дату. Загружай `transactions.csv` и `transfers.csv` отдельно. Сначала изучи предпросмотр, ошибки и кандидатов в дубли. Создание отсутствующих категорий/тегов включай только если это согласуется с намерением пользователя. При ошибке, невыясненной строке или расхождении сверки не подтверждай импорт.
- Если пользователь попросил именно провести импорт и все строки сверены, подтверди batch и проверь остатки счетов и прогноз по каждой валюте. Если пользователь просил только подготовить данные, отдай CSV без записи в приложение.
- В финальном отчёте укажи число строк PDF, исключённые/неразобранные строки, число строк каждого CSV, суммы по счетам и валютам, способ получения курсов и оставшиеся вопросы. Не скрывай неопределённость OCR или расхождения.

Если текущая версия приложения предлагает другой шаблон колонок на странице импорта, скачай его там и следуй отображаемому формату. Не требуй от пользователя доступа к исходному коду или локальным файлам проекта.
